# Кабинет заказчика после выделения модулей

Ветка `refactor/quality`, исходная версия для сравнения — `d0aab5b`.
Изменения касаются кабинета заказчика и повторяющихся утилит.
CSS, изображения, анимации, тарифы, авторизация и схема хранения сохранены.

## Структура

```text
dist/
  customer.js                — загрузка модулей и совместимость со старой инициализацией
  shared.mjs                 — деньги, даты, HTML-экранирование, ID, склонение числительных
  customer/
    state.mjs                — состояние кабинета, пустой черновик, статусы и сессия
    storage.mjs              — чтение/сохранение JSON, проверка конфликтов, IndexedDB
    orders.mjs               — расчёт через OrderMath, фильтры, создание и изменение заказов
    views.mjs                — HTML страниц, карточек, этапов печати и диалогов
    actions.mjs              — конкретные действия пользователя и делегирование событий
    controller.mjs           — связывание модулей, DOM, PDF-загрузка, показ страниц и окон
```

`createCustomer()` создаёт независимое состояние и принимает зависимости явно:
`window`, `document`, `storage`, `indexedDB`, `orderMath`, `ui`, `studio`, `notify`.
Тесты передают отдельное хранилище в памяти; приложение — существующие браузерные API.
`orders.mjs` не обращается к DOM. `views.mjs` не записывает данные и получает
декоративную PDF-разметку через `pdfArtwork`. Запись заказов проходит через repository;
сообщение об успехе появляется после успешного сохранения.

Создание PDF-заказа, заказа коллекции и заказа конструктора отделено от отображения.
Общая структура нового заказа формируется в одном месте. Отмена, ответы, повтор
документа и демонстрационная смена статуса также находятся в `orders.mjs`.
Обработчик кликов выбирает конкретное действие; формы, поля и клавиатура обрабатываются
отдельно. Шаблоны разделены по смыслу: приветствие, hero, услуги, настройки печати,
параметры заказа, вложения, история и действия. Конкатенация строк сохраняет исходные
пробелы в выводимом HTML. Одинаковая SVG-стрелка используется через один шаблон;
её исходные атрибуты, в том числе толщина линии, сохранены.

Повторяющиеся форматирование денег/дат, экранирование и генерация ID вынесены
из customer/staff/studio/controls в `shared.mjs`. `staff.js`, `studio.js`, `controls.js`
получают нужные утилиты при инициализации; их остальная реализация сохранена.

## Загрузка и совместимость

В `index.html` кабинет подключён как стандартный ES Module. Модульный граф готов
до запуска классического `app.js`: customer.js инициализирует Studio, Customer, Staff,
затем загружает app.js и запускает Controls. Публичные `window.Customer`, `window.Studio`,
`window.Staff` сохранены. Вспомогательные `initializeStudio/Staff/Controls` служат мостом
для этой последовательности. app.js, living.js, ui.js и OrderMath не переписаны.
Порядок подключения CSS не менялся.

Сайт запускается по HTTP командой `npm.cmd start` (порт 8080).
Локальный сервер уже отдаёт `.mjs` с JavaScript MIME-типом. Будущий статический
хостинг также должен поддерживать этот MIME-тип; сборщик не требуется.

Ключи `okei-customer-v1:<логин>`, база `okei-customer-files`, версия 1 и хранилище
`files` не менялись. Миграций и очистки пользовательских данных нет.
Сохранены merge/check-before-write для К1, обработка отказа записи для К2
и проверка владельца/версии сессии после ожиданий для К3.

## Проверки

До изменений: 30 Node-тестов и 6 сценариев Edge прошли.
После изменений: 45 Node-тестов, исходные регрессии К1–К3 и браузерные проверки
описаны в `tests/README.md`. Новые тесты проверяют утилиты, изоляцию состояния,
фильтры, диапазоны, повтор документа и переходы статусов. Девять SHA-256 отпечатков
проверяют точное совпадение HTML с исходной версией; автоматического обновления нет.

Для визуального сравнения исходный коммит распакован во временный каталог,
обе версии запускались на разных локальных портах с отдельными BrowserContext.
Сравнены 12 экранов: главная в двух темах, вход, кабинет в двух темах, параметры PDF,
заказ, коллекция, конструктор, очередь сотрудника, мобильная очередь и мобильная главная.
Условия: Edge, 1440×1000 / 390×844, DPR 1, ru-RU, Asia/Yekaterinburg,
фиксированное время и одинаковые данные. Ожидались шрифты и завершение переходов.

В 9 снимках различий пикселей нет. В трёх отличаются соответственно 9, 3 и 9 пикселей
с максимальной разницей канала 1 из 255. Сравнение исходного коммита с самим собой
воспроизводит аналогичный шум растеризации. Изменений вёрстки не обнаружено;
абсолютная побитовая идентичность всех PNG не заявляется. Утверждённые эталоны
не перезаписывались. Снимки, временная исходная копия и отчёты не включены в Git.

## Следующие границы изменений

staff.js, studio.js и app.js по-прежнему крупные классические скрипты и используют
глобальные мосты. Их разделение можно выполнять следующими независимыми этапами.
В views.mjs остаётся большой объём статической разметки, но функции сгруппированы
по страницам и смысловым блокам. Полной валидации повреждённых сохранений пока нет.
localStorage не обеспечивает транзакции между вкладками; после прерванных операций
могут оставаться Blob без ссылок. Эти прежние ограничения не исправлялись в рамках
архитектурного изменения. Авторизация, роли и переписка остаются локальной демонстрацией.
